## 1. 시스템 구조

### 1.1 통신 경로 (규격서 기준)
```
슈퍼게이트(S/G/W) → 모트렉스 제어기 → 차종차 H/U(네비) → STI Display
```

### 1.2 현재 테스트 구성
```
Jetson AGX Thor (USB Device) --USB-C--> 게이트웨이 장비 --내부통신--> 네비게이션
       ttyGS0 (CDC ACM)                   (호스트)
       FunctionFS (Bulk)
```

- **Jetson = USB Device (가젯 모드)**
- **게이트웨이 = USB Host**
- **네비게이션 = 최종 표시 장치**
- Jetson USB-C 포트가 디바이스 모드로 동작 (`tegra-xudc`)
- 게이트웨이가 Jetson과 네비 사이에 물리적으로 존재

### 1.3 Jetson USB 포트 구성
| 포트 | 용도 | 비고 |
|------|------|------|
| `/dev/ttyGS0` | USB-C 가젯 시리얼 (게이트웨이 연결) | CDC ACM |
| `/dev/ttyACM0` | ADI BLE 동글 (워치) | **절대 사용 금지** |
| USB-A 호스트 | 카메라, 키보드, 마우스, 마이크 등 | lsusb로 확인 |

## 2. 프로토콜 규격

### 2.1 변경 이력
| 날짜 | 내용 |
|------|------|
| 2026-03-30 | 초기 13-byte (DATA_LEN 3바이트, BODY[0] 비트패킹) |
| 2026-04-03 | **12-byte로 변경** (DATA_LEN 2바이트, BODY[0] 감정코드 full byte) |

변경 근거: 모트렉스 신사업기획팀 박정현 위원 메일

### 2.2 현재 패킷 구조 (12-byte, 모트렉스 규격)
```
Byte  0: STX         = 0x02        시작바이트
Byte  1: VERSION     = 0x01        프로토콜 버전
Byte  2: RESERVED_H  = 0x00        Reserved
Byte  3: RESERVED_L  = 0x00        Reserved
Byte  4: DEST        = 0x10        목적지 (0x10=모트렉스, 0x00=슈퍼게이트)
Byte  5: DATA_LEN[0] = 0x03        Data Length LSB (COMMAND+BODY = 3)
Byte  6: DATA_LEN[1] = 0x00        Data Length MSB
Byte  7: COMMAND     = 0xF0        명령어
Byte  8: BODY[0]     = 감정코드     full byte (이전: upper nibble + flags)
Byte  9: BODY[1]     = 강도         [감정강도 D7~D5][상태강도 D4~D2][Reserved D1~D0]
Byte 10: CHECKSUM    = XOR         Byte0 ~ Byte9 XOR
Byte 11: ETX         = 0x03        종료바이트
```

### 2.3 이전 구조와 비교 (13-byte → 12-byte)
| 항목 | 이전 (13-byte) | 현재 (12-byte) |
|------|---------------|---------------|
| DATA_LEN 필드 | 3바이트 (Byte 5~7) | **2바이트 (Byte 5~6)** |
| BODY[0] | [감정코드 D7~D4][Stress D3][LowAttn D2][Drowsy D1][Rsvd D0] | **감정코드 full byte** |
| 상태 플래그 | BODY[0]에 포함 | **제거됨** |
| 패킷 크기 | 13 bytes | **12 bytes** |
| Neutral 코드 | 0x0F | **0xFF** |

### 2.4 감정 코드 매핑
| 프로토콜 코드 | 감정 (한글) | K-FER ID | K-FER 라벨 |
|--------------|-----------|----------|-----------|
| 0x00 | 공포 | 1 | anxious |
| 0x01 | 놀람 | 6 | surprised |
| 0x02 | 분노 | 0 | angry |
| 0x03 | 슬픔 | 5 | sad |
| 0x04 | 행복/기쁨 | 2 | happy |
| 0x05 | 혐오 | 3 | hurt |
| 0xFF | Reserved(중립) | 4 | neutral |

### 2.5 BODY[1] 강도 바이트
```
비트:  D7 D6 D5 | D4 D3 D2 | D1 D0
       감정강도    상태강도    Reserved
       (0~7)      (0~7)      (00)

예시:
  FC = 111 111 00 → 감정7/7, 상태7/7
  E8 = 111 010 00 → 감정7/7, 상태2/7
  D4 = 110 101 00 → 감정6/7, 상태5/7
  C8 = 110 010 00 → 감정6/7, 상태2/7
```

### 2.6 전송 패킷 예시 (전부 감정7, 상태7)
```
[공포]  02 01 00 00 10 03 00 F0 00 FC 1C 03  ← 모트렉스 메일 예시와 100% 일치
[놀람]  02 01 00 00 10 03 00 F0 01 FC 1D 03
[분노]  02 01 00 00 10 03 00 F0 02 FC 1E 03
[슬픔]  02 01 00 00 10 03 00 F0 03 FC 1F 03
[행복]  02 01 00 00 10 03 00 F0 04 FC 18 03
[혐오]  02 01 00 00 10 03 00 F0 05 FC 19 03
```

### 2.7 양방향 통신
```
슈퍼게이트→모트렉스: 02 01 00 00 10 03 00 F0 00 FC 1C 03  (DEST=0x10)
모트렉스→슈퍼게이트: 02 01 00 00 00 03 00 F0 00 FC 0C 03  (DEST=0x00)
```

## 3. 시행착오 기록

### 3.1 CDC ACM (시리얼) 시도

**방법:** Jetson USB-C 가젯 포트(`ttyGS0`)를 CDC ACM 시리얼로 사용

**결과:**
- 노트북 연결: **성공** (TX OK, 노트북 COM 포트에서 수신 확인)
- 게이트웨이 연결: **실패** (TX OK이지만 네비에 표시 안 됨)

**상세 로그:**
```
[1/6] 공포 TX OK (12B) | 02 01 00 00 10 03 00 F0 00 FC 1C 03
[2/6] 놀람 TX OK (12B) | 02 01 00 00 10 03 00 F0 01 FC 1D 03
[3/6] 분노 TX OK (12B) | 02 01 00 00 10 03 00 F0 02 FC 1E 03
[4/6] 슬픔 TX OK (12B) | 02 01 00 00 10 03 00 F0 03 FC 1F 03
[5/6] 행복 TX OK (12B) | 02 01 00 00 10 03 00 F0 04 FC 18 03
[6/6] 혐오 TX OK (12B) | 02 01 00 00 10 03 00 F0 05 FC 19 03
```

**문제 분석:**
- `setup request failed: -95` (dmesg) → 호스트가 CDC ACM 미인식
- TX OK는 USB 버퍼에 들어간 것이지, 게이트웨이가 읽은 것은 아님
- 게이트웨이에서 응답(RX) 없음
- agetty가 ttyGS0을 점유하는 문제 → `systemctl stop serial-getty@ttyGS0.service`로 해결

**조치:**
- agetty 중지: `sudo systemctl stop serial-getty@ttyGS0.service`
- 권한 설정: `sudo chmod 666 /dev/ttyGS0`
- write_timeout 설정으로 블로킹 방지

### 3.2 USB Mass Storage 시도

**방법:** Jetson을 USB 메모리(Mass Storage)로 인식시켜 파일로 패킷 전달

**결과:** **부분 성공/실패**
- 네비에서 "미디어 장치"로 인식됨 → 물리적 연결 확인
- "재생 가능한 미디어가 없다" 표시 → 바이너리/텍스트 파일은 재생 불가
- 실시간 통신 불가 (파일 기반이라)

**상세:**
- 기존 이미지: `/opt/nvidia/l4t-usb-device-mode/filesystem.img` (FAT16, 16MB, ro)
- 새 이미지 생성: `/tmp/kmer_usb.img` (FAT, 32MB, rw)
- UDC 해제 → 이미지 교체 → UDC 재연결로 Hot-swap

**문제:**
- 이미지가 read-only로 마운트되는 문제 (가젯이 사용 중일 때)
- UDC를 해제해야 이미지 교체 가능

### 3.3 USB Bulk Transfer 시도

**방법:** FunctionFS로 커스텀 Bulk IN/OUT 엔드포인트 생성

**결과:** **가젯 생성 성공, 전송 블로킹**

**시행착오:**

1. **FunctionFS v2 디스크립터 실패 (EINVAL)**
   - FS+HS+SS (105B) → 실패
   - FS+HS only (66B) → 실패
   - FS only (39B) → 실패
   - 원인: 커널 6.8 FunctionFS가 v2 포맷을 기대하는 방식이 다름

2. **FunctionFS v1 디스크립터 성공**
   - v1 magic (=1) 사용
   - `struct.pack('<IIII', 1, length, fs_count, hs_count)` 형식
   - FS+HS 동일 디스크립터 (512B max packet)

3. **Strings 실패 → 해결**
   - `str_count=1, lang=1, empty string` → EINVAL
   - `str_count=0, lang=0, header only (16B)` → **성공**
   - `struct.pack('<IIII', 2, 16, 0, 0)`

4. **엔드포인트 생성 성공**
   - EP0 (control), EP1 (Bulk OUT), EP2 (Bulk IN) 생성 확인
   - **EP0를 열어둔 상태에서만 EP1/EP2 유지** (EP0 닫으면 사라짐)

5. **EP2 write 블로킹**
   - `os.write(ep2, packet)` 에서 블로킹
   - 호스트(게이트웨이)가 Bulk IN 데이터를 읽지 않음
   - CDC ACM과 동일한 증상

**최종 동작 코드 (FunctionFS v1):**
```python
import struct, os

intf = bytes([9, 4, 0, 0, 2, 0xFF, 0, 0, 0])
ep_out = struct.pack('<BBBBHB', 7, 5, 1, 2, 512, 0)
ep_in  = struct.pack('<BBBBHB', 7, 5, 0x81, 2, 512, 0)
descs = intf + ep_out + ep_in

# v1 descriptor
blob = struct.pack('<IIII', 1, 16 + len(descs)*2, 3, 3)
blob += descs + descs

fd = os.open('/dev/usb-ffs/bulk0/ep0', os.O_RDWR)
os.write(fd, blob)
os.write(fd, struct.pack('<IIII', 2, 16, 0, 0))  # empty strings
# fd를 열어둔 채로 UDC 활성화 필요
```

### 3.4 시도 결과 요약
| 방식 | 가젯 생성 | 노트북 연결 | 게이트웨이 연결 | 비고 |
|------|----------|-----------|--------------|------|
| CDC ACM | ✓ (L4T 기본) | ✓ TX OK | ✗ TX OK but 미수신 | setup request -95 |
| Mass Storage | ✓ (L4T 기본) | - | △ 미디어로 인식 | 실시간 통신 불가 |
| Bulk (FFS v2) | ✗ EINVAL | - | - | 디스크립터 포맷 불일치 |
| Bulk (FFS v1) | ✓ EP 생성됨 | - | ✗ write 블로킹 | 호스트 미수신 |

## 4. USB 가젯 설정 참고

### 4.1 L4T 기본 가젯 구성
```
/sys/kernel/config/usb_gadget/l4t/
├── configs/c.1/
│   ├── acm.GS0         → CDC ACM 시리얼
│   ├── mass_storage.0   → USB 메모리
│   ├── rndis.usb0       → 네트워크
│   └── ncm.usb0         → 네트워크
├── functions/
│   ├── acm.GS0
│   ├── mass_storage.0
│   ├── rndis.usb0
│   └── ncm.usb0
└── UDC = a808670000.usb
```

### 4.2 가젯 함수 변경 절차
```bash
# 1. UDC 해제
echo "" | sudo tee /sys/kernel/config/usb_gadget/l4t/UDC

# 2. 기존 함수 제거 (심볼릭 링크)
sudo rm /sys/kernel/config/usb_gadget/l4t/configs/c.1/acm.GS0

# 3. 새 함수 추가
sudo ln -s .../functions/xxx .../configs/c.1/xxx

# 4. UDC 재연결
echo a808670000.usb | sudo tee /sys/kernel/config/usb_gadget/l4t/UDC
```

### 4.3 FunctionFS Bulk 가젯 설정 절차
```bash
# 1. FFS 함수 생성
sudo mkdir -p /sys/kernel/config/usb_gadget/l4t/functions/ffs.bulk0
sudo ln -s .../functions/ffs.bulk0 .../configs/c.1/ffs.bulk0
sudo mkdir -p /dev/usb-ffs/bulk0
sudo mount -t functionfs bulk0 /dev/usb-ffs/bulk0

# 2. Python에서 EP0에 디스크립터 쓰기 (v1 형식)
# 3. EP0 열어둔 상태에서 UDC 활성화
# 4. EP1(OUT), EP2(IN) 사용
```
